# 🧩 DSA Track — from "forgot everything" to interview-ready (Java)

> **Mission:** rebuild your college DSA strength in Java and convert it into *pattern recognition + clean code under time pressure*.
> **30 weeks:** Mon 26 Oct 2026 → Sun 23 May 2027 · Mon–Sat 60 min (first block of the day) · Sunday = weekly test.

## 🎯 By Week 30 you will…
- Have solved **294 core problems** (57 Easy · 204 Medium · 33 Hard) + up to **202 bonus** — all free on LeetCode (no Premium).
- Have re-solved **176 of them** on a fixed spaced schedule (built into every week file), plus 36 timed re-solves in the two re-solve weeks.
- Recognise **25+ patterns** within ~2 minutes of reading a problem (see [PATTERNS_CHEATSHEET.md](PATTERNS_CHEATSHEET.md)).
- Solve most Mediums in **20–25 min** and common Hards in **~40 min**, talking aloud like in a real interview.
- Have 9 LeetCode contests, 4 online-assessment simulations and 10 talk-aloud mocks behind you (from W20 you talk through a problem every week).

> **Honest note on "95% of interview questions":** no list can guarantee every question. What *does* work is covering every
> major pattern with enough reps, re-solving on a schedule, then practising unseen problems (contests, mocks, company lists).
> This plan is built exactly for that.

## 🔁 How to run one 60-minute session
1. **10–20 min — Re-solve** the problem(s) in today's "Daily re-solve" row from memory, timed (targets: Easy 10 · Medium 20 · Hard 35 min). Can't finish? Mark it 🔴.
2. **~40 min — New problems:**
   - Read → write 2 examples + 1 edge case → say the brute force (and its complexity).
   - Time-box the first attempt (Easy 15 / Medium 25 / Hard 40 min, shown in each week file).
   - Stuck? Watch **only the intuition** part of a video (Striver / NeetCode / Aditya Verma), **close it**, code from memory.
   - After AC: check time & space complexity, then read 1 top-voted solution for a cleaner idea.
3. **5 min — Log it** in [REVISION_TRACKER.md](REVISION_TRACKER.md): pattern · key insight · time · 🟢/🟡/🔴.
4. **2 min (any time today) — Talk aloud:** record a short explanation of one problem (approach, complexity, one edge case).

**Rules:** Java only · no copy-paste · if you used a hint, mark 🟡 · if you needed the full solution, mark 🔴.

## 🔄 The re-solve system (already planned in every week file)
- **Weekdays:** 1 re-solve from the same weekday of the previous problem week (D+7; in Week 1 it is yesterday's problem).
- **Saturday:** 1–2 quick timed re-solves (Easy/Medium first) from 3 weeks earlier (D+21) — only 1 when Saturday's new problems already need more than 50 min.
- **Fair rotation:** re-solves are planned once in calendar order, least-re-solved first, so no problem comes back more than twice while others wait (176 different problems get re-solved).
- **Sunday preview slot:** re-solve this week's 🔴 problems; stubborn 🔴 items go to the mentor's fix-it list.
- **Re-solve weeks (no new problems, no extra daily re-solves):** W26 = 2 a day, light (AI-200 exam week) · W30 = the final speed-run, 4 a day.

## ⚠️ Pitfalls to avoid
- **Video binging** — watching 5 solutions feels productive but builds nothing. One intuition, then code.
- **Skipping Easy problems** — W1–W2 Easies rebuild Java syntax speed; don't skip them.
- **Skipping the daily re-solve** — it is only 10–12 minutes and it is where retention happens. Do it first, before new problems.
- **Ignoring complexity** — always state time/space before submitting.
- **Hard-problem ego** — if a Hard takes > 60 min, read the solution and mark 🔴; it comes back in the re-solve rows, the W27 Hard bank and the W30 speed-run.
- **Only practising known patterns** — from W6 the Sunday test includes an unseen problem; contests, mocks and company lists are the real benchmark.

## 📝 How you're tested on Sundays (45 min)
- **2 timed problems in Java that are not in the plan** — Q1 on this week's pattern; **from W6, Q2 is an unseen problem from an earlier pattern** (no hint which). Write the approach in 2–3 lines first (5 marks per problem), then code; paste your code to the AI mentor.
- **5 pattern-recognition one-liners** ("which pattern and why?").
- **Contest Sundays (W10, W12, W14, W16, W18, W22, W24, W26, W28 — the boss weeks W20 and W30 run the boss test instead):** the LeetCode Weekly Contest (8:00 AM IST, 90 min) replaces this section; up-solve one missed problem during the week and log it.
- **Mocks:** start in W15 — on non-contest Sundays the first problem is a talk-aloud mock (the mentor plays the interviewer), so mocks alternate with contest Sundays; from W20 you also explain your contest up-solve aloud, so you talk through a problem every week.
- **Online assessments:** from W12 re-solve one problem every 2 weeks as a full stdin/stdout program (fast-I/O template #36); timed OA simulations in W19–W20 and W29.
- **Boss weeks (W4, W9, W15, W20, W25, W30):** Saturday's 2 problems are a timed Boss Battle (W25 = virtual contest) and Sunday's test is a little harder; W30 = full mock interview loop.
- Graded on correctness, complexity, edge cases, and code clarity. **≥ 80 🟢 · 60–79 🟡 · < 60 🔴** → 🔴 topics get remediation problems next week.
